# Monotainer Agent Guide

Сводка практик и правил, которые мы выработали в ходе разработки расширения.
Используй этот документ как точку входа, чтобы не перечитывать всю переписку.

## Общие правила работы

- **Никогда не создавай коммиты и не пушь изменения без прямого запроса пользователя.**
- Для любых рискованных действий (rebase, force push) сперва уточняй у пользователя.
- Перед выполнением git-команд, влияющих на историю, убедись, что набор коммитов существует
  (например, `HEAD~3` был недоступен, потому что в истории было только три коммита).
- Сборка TypeScript обязательна: `npm run compile`.
- Пакет собираем через `npx vsce package`. Публикация в Marketplace возможна только через VS Code Marketplace под издателем `monosyde`.
- Локальный VSIX можно установить в Cursor/VS Code через `Extensions → Install from VSIX…`.

## Конвенции проекта

- **Название и издатель:** `monotainer` / `monosyde`. Текущее отображаемое имя — "Monotainer: Docker Dashboard".
- **Минимальная версия VS Code:** `^1.99.0` (Cursor основан на VS Code 1.99.x).
- **Лицензия:** MIT (`LICENSE`).
- **package.json** всегда содержит блок `repository` с `https://github.com/monosyde/monotainer.git`.
- **Структура локализации:**
  - `src/locales/en.ts`, `src/locales/ru.ts`, типы в `src/locales/types.ts`.
  - `src/localization.ts` экспортирует `localize`, `resolveLocale`, `getAllMessages`.
- **Дашборд:**
  - HTML/JS/CSS в `media/` (`dashboard.html`, `dashboard.js`, `styles.css`).
  - Коды UI живут в классе `DashboardApp` с JSDoc.
  - Переводы загружаются из расширения и доступны в webview.
- **Backend:** все Docker-команды инкапсулированы в `src/services/dockerService.ts`.
  Дополнительные утилиты — `src/utils/command.ts`.

## Взаимодействие Webview ↔ Extension

- **Сообщения webview → extension:**
  - `refresh` — обновление списков.
  - `select` — запрос деталей конкретного ресурса.
  - `containerAction`, `imageAction`, `volumeAction` — действия над сущностями.
  - `exec` — открыть `docker exec` терминал.
  - `changeLocale` — переключение языка.
  - `loadMoreLogs` — запрос доп. строк логов (контейнер).

- **Ответы extension → webview:**
  - `state` — новые списки.
  - `detail` — подробности ресурса (`detail.logLines` включено для контейнеров).
  - `status` / `actionResult` / `error` — сообщения о состоянии.
  - `logsMore` — результат подгрузки логов (содержит `logLines` и `logStep`).

## UX-требования

- Три ресурсных вкладки: **Containers**, **Images**, **Volumes**.
- Для контейнеров доступны действия: Start, Restart, Stop, Remove, Exec.
- В карточке контейнера есть кнопка “Load more logs” — догружает логи пакетами (`300` строк, шаг `300`).
- Независимые скроллы для списков, вкладок и логов.
- Два столбца (список ↔ детали) разделены draggable-сплиттером (границы 20–80%).
- Селектор масштаба (`70–100%`) влияет на всю панель (`--dashboard-zoom`).
- Локализация ru/en; переключение языка в тулбаре.
- По умолчанию логов загружается `300` строк.

## Дополнительные замечания

- После squash в `init` история стоит из одного коммита; любые новые изменения следует коммитить только после подтверждения пользователя.
- При переполнении логов не забывай обновлять `containerLogState` и отключать кнопку «Load more logs», если контейнер не выбран.
